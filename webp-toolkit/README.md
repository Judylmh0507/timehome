# Timehome 独立站图片优化工具包（Mac 终端一键版）

这个工具包会自动完成三件事：
1. 把文件夹里的 JPG 批量转成同名 WebP（**原 JPG 一张都不删、不改**）；
2. 往网站仓库根目录写入缓存配置 `_headers`，让图片/样式/脚本在 CDN 上缓存 30 天，不再每次回源拉取；
3. 自动提交 Git 并推送到 GitHub（Pages / Netlify 会自动重新部署）。

---

## 第一次使用前的准备（只做一次）

电脑上需要有 Node.js。检查方法：打开「终端」，输入 `node -v` 回车。
- 如果显示版本号（比如 `v22.x.x`）：不用装，直接看下面步骤。
- 如果提示 `command not found`：去 https://nodejs.org 下载 **LTS 版**，打开安装包一路点「继续」装好，再重开终端。

---

## 三步操作

### 第 1 步：把工具包解压到你的网站项目文件夹里
把解压出来的这几个文件，放到和你网站代码同一个文件夹（也就是能看到 `.git` 那个文件夹）里：
```
run.sh
convert-webp.mjs
_headers
package.json
```

### 第 2 步：打开终端，进入项目文件夹
最简单的方式：在访达里打开项目文件夹，按住 `Option` 键右键文件夹 → 选「服务」→「新建位于文件夹的终端窗口」。
（或者终端里输入 `cd ` 后把文件夹拖进窗口，回车。）

### 第 3 步：运行脚本，把图片文件夹拖进去
在终端输入下面这行，先别回车：
```
bash run.sh
```
然后把存放产品图片的那个文件夹（就是一堆 `i46-333-1.jpg` 所在的文件夹）从访达拖到终端窗口里，路径会自动填上去，最后回车。

例如终端里最终是这样：
```
bash run.sh /Users/你的名字/website/images
```

脚本会自动：装依赖（约半分钟，仅第一次）→ 转 WebP → 写缓存配置 → 提交并推送。
看到 `全部完成！` 就结束了。如果最后提示「还没关联 GitHub 远程地址」，说明本地仓库没绑 GitHub，把仓库远程地址配好后重跑一次即可。

---

## 跑完之后，去 Cloudflare 后台点两个地方（必须做）

### 1. 关闭 HTTP/3（解决图片一直转圈、加载十分钟的最常见原因）
Cloudflare 控制台 → 选中你的域名 `timehome.top` → 左侧 **Network** → 找到 **HTTP/3 (QUIC)** → 关掉开关。

### 2. 清一次缓存
左侧 **Caching** → **Purge Cache** → **Purge Everything**。
等 1–2 分钟，再强刷网站看效果。

---

## 说明与注意

- **原图保留**：转换后每张 JPG 旁边多一个同名 `.webp`，JPG 本身不动，随时可回退。
- **损坏图片**：打不开的坏图会被跳过并在结尾列出来，需要你在本地重新导出那张图。
- **图片尺寸**：长边超过 1200px 的会压到 1200px；已经更小的不会被放大。
- **HTML 还在引用 JPG**：本次先生成 WebP 备用并配好缓存。要让浏览器优先加载 WebP，需要改产品页模板（用 `<picture>` 标签）；这一步要看到网站源码后再动，避免改坏页面。需要时把项目代码发我，我来改。
- 改完部署后，可以用 https://pagespeed.web.dev 测一下产品页速度。
